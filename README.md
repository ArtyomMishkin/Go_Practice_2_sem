## Назначение

Репозиторий содержит реализацию практических занятий №1–№16 по разработке на Go. Материалы организованы в виде изолированных каталогов с единым соглашением об именовании (`pzN-<тема>`). В каждом каталоге размещены исходный код, описание выполненного задания, инструкция по развёртыванию и, при необходимости, сценарии автоматизированной проверки (`start-*.ps1`, `tests.ps1`).

Вспомогательный конспект по темам занятий — [Шпаргалка.md](Шпаргалка.md).

## Получение и использование материалов

### Полный архив репозитория

Предпочтительным способом работы с материалами является получение **полной копии** репозитория (операция `git clone` либо загрузка архива целиком). Данный подход гарантирует:

- целостность структуры каталогов;
- наличие конфигурационных файлов CI/CD в корне (требование занятия №8);
- сохранение логических связей между работами (например, сервис tasks, введённый в pz7 и используемый в pz10, pz13–pz14).

Проверка отдельной работы выполняется путём перехода в соответствующий каталог и следования инструкции в файле `README.md` данного каталога.

### Изолированный каталог одной работы

Допускается использование **отдельного** каталога (`pzN-...`) без остальных работ. В этом случае необходимо учитывать ограничения, приведённые ниже.

| Условие | Описание |
|---------|----------|
| Конфигурация CI/CD | Для занятия №8 файлы `.github/workflows/*.yml` и `.gitlab-ci.yml` должны располагаться в **корне** репозитория, а не в каталоге `pz8-ci-cd`. При отсутствии — см. [pz8-ci-cd/README.md](pz8-ci-cd/README.md). |
| Сетевые порты | Сводная таблица — в разделе [Сетевые порты](#сетевые-порты). Параллельный запуск двух работ на одном порте несовместим. |
| Внешние компоненты | Отдельные работы опираются на Docker, PostgreSQL, Redis или RabbitMQ (перечень — в README работы). При недоступности контейнерной среды в ряде README описан альтернативный локальный запуск. |
| Структура модулей Go | Работа №1: модули `user-service` и `order-service`. Работа №7: модули `auth` и `tasks`. Сборка и тестирование выполняются из каталога соответствующего модуля. |
| Платформа | Скрипты — **PowerShell** (Windows). В каждом каталоге есть раздел **«Запуск без PowerShell»** (CMD / bash). Требуется **Go 1.22+**. |

## Структура корневого каталога

```
Go_Practice_2_sem/
├── README.md
├── Шпаргалка.md
├── .github/workflows/
├── .gitlab-ci.yml
├── pz1-microservices/
├── pz2-grpc/
└── …
```

Каталог `.github/workflows` и файл `.gitlab-ci.yml` относятся к занятию №8 и обеспечивают запуск конвейера CI при отправке изменений на GitHub и GitLab соответственно.

## Процедура запуска и проверки

1. Открыть каталог интересующей работы.
2. Изучить `README.md` в этом каталоге.
3. Запуск: скрипт `start-*.ps1` (PowerShell) **или** раздел **«Запуск без PowerShell»** (CMD / bash).
4. При наличии — выполнить `tests.ps1` или команды проверки из README.
